# 选区存在不等于视口应跟随

编辑器必须区分“逻辑选区仍然有效”和“用户希望视口定位到该选区”这两个意图。文档事务可以映射、保留或改变 ProseMirror 选区，但不得仅凭 `docChanged` 或 `selectionSet` 就滚动到选区；只有明确的光标操作意图才能请求显示选区。

允许视口跟随选区的场景只有：工具栏隐藏时点击窗口下沿正文，工具栏出现后需要移动文档以保证新光标可见；用户直接输入、删除、粘贴文字或用键盘移动选区；以及撤销或重做原本要求跟随选区的编辑操作。任务勾选、行拖动删除或移动、折叠、工具栏格式化等块级或控件操作应保持当前文档位置，即使内部仍存在旧光标或事务重新映射了选区。

撤销和重做必须恢复历史记录中的逻辑选区，但视口意图继承原操作：文字输入、删除、粘贴等光标驱动操作恢复选区后，在编辑器已聚焦时以最小滚动量保证光标可见；任务勾选、行操作、折叠和工具栏格式化的撤销与重做保持视口。编辑器失焦时的全局撤销和重做不得抢占焦点、显示工具栏或滚动文档。若折叠会隐藏当前选区，应把逻辑选区移到对应的折叠标题，同时保持该标题的视觉位置。

实现和回归测试应让“请求显示选区”成为显式信号，并让进入撤销历史的事务同时记录其视口意图；新增编辑器事务或命令时，默认保持视口，除非它属于上述允许场景。测试至少要覆盖进入便签后未点击正文便直接勾选或拖动删除，以及撤销、重做这些操作的路径，断言视口不会跳到文档开头。
